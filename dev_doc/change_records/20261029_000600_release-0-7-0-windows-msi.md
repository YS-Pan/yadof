# 2026-10-29 00:06 - Publish yadof 0.7.0 and the Windows MSI

The user requested committing the current source to a non-empty GitHub branch
and publishing the MSI as release 0.7.0 in YS-Pan/yadof. The working tree included
previously completed GUI, history, distributed-execution and administrator-tool
changes together with their tests and change records.

## Change and rationale

- Set the single runtime version to 0.7.0 and update its package assertion,
  current installation examples, foundation blueprint and README. Add the 0.7
  milestone to the version history. Historical version and migration records keep
  their original versions; yadof-benchmark remains a separate distribution.
- Preserve the current source history on release/v0.7.0, with v0.7.0 pointing to
  that release commit. Include framework source, focused tests, administrator
  scripts and documentation. Local task workspaces, editor settings, scratch
  evidence, the HFSS handoff ZIP and generated distribution files are excluded
  from the Git commit. Only newline encoding was normalized in the uncommitted
  modern-MSI change record; its historical text is preserved.
- Rebuild the wheel and MSI from this source. The MSI retains the A2094 dependency
  pins, modern folder chooser, real installer progress and private yadof_env.
  HTCondor, frp and solver packages are provisioned separately. Distribution
  archives are release attachments rather than Git-tracked binaries.

## Validation and evidence

The package suite runs against the regular wheel installation in ../.venv with
source injection disabled. The administrator suites exercise isolated fixtures.
Release acceptance uses MSI copies with separate product/package/upgrade/component
identities, registry keys and shortcuts, preserving the existing user installation.
It exercises installation, private/native dependencies, GUI controller, installed
documents, a bounded generic local task, repair, same-version replacement,
0.6-to-0.7 replacement, downgrade rejection and uninstall. Unknown files and an
external workspace remain user-owned.

The published acceptance report identifies the actual tested MSI digest and its
QA-copy scope. SHA-256 sidecars and the dependency/file manifest accompany the

The folder-picker implementation and UI contracts are unchanged from the preceding
