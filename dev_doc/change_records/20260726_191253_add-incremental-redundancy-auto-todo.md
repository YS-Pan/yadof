# 2026-07-26 19:12 - 新增渐进式冗余清理自动 toDo

## 背景

- yadof 主要由 AI 生成和维护，连续修改容易不断叠加代码，而缺少对既有冗余的主动
  复查。
- 用户希望建立一份中文自动 toDo，在后续工作自然接触代码时检查并改善冗余，同时
  避免一次修改过多文件。

## 变更

- 新增持续有效的自动 toDo，规定只在正常任务自然暴露冗余时触发。
- 将每次清理限制为一个明确问题和最多一至两个文件，并把测试、文档、配置也计入文件
  数量。
- 增加了冗余判断证据、不可机械删除的契约、简化原则、验证要求和简短文字汇报格式。

## 原因

- 小范围、行为保持的清理更容易审查和验证，也能防止“清理冗余”演变为未经授权的
  全仓重构。
- 先检查调用、导出、测试和文档，可以区分真正重复的实现与公共 API、故障隔离、
  并发或平台契约。
- 使用 `manual` 过期规则可使这项持续维护约束不会在默认七天后自动失效。

## 影响

- 仅影响后续维护者在自然工作范围内处理代码冗余时的操作方式和汇报要求。
- 未修改 yadof package 代码、架构、蓝图、术语或 agent-facing 任务编写行为。

## 后续

- 后续每次触发均应独立控制在一至两个文件，并在验证后进行简短文字汇报。
