# Project-specific terminology

| Term | Meaning |
|---|---|
| `agent-led workflow` | The normal yadof usage path: a human user directs an AI coding agent, preferably the Codex reference used during development, and the agent reads version-matched installed user guidance before authoring or validating an explicit workspace. The agent is not copied into jobs and does not replace the CLI/API runtime contract. |
| `installed package` | The complete `yadof` framework under site-packages: APIs, CLI, defaults, templates, adapters, worker support, tools, and read-only docs. It is not a runtime write location. |
| `yadof-benchmark package` | Independent distribution under top-level `yadof-benchmark/`. It owns the console command, public API, code-first workspaces, self-describing baselines, version-matched documents, and focused tests; it depends on public yadof behavior and yadof does not depend on it. |
| `benchmark workspace` | One timestamped root containing one editable `benchmark.py` and one direct execution. Another execution uses another workspace. Runtime/spec/state, short cells, results, reports, and visualizations are direct children; there is no run ID, `runs/`, resume surface, or attempt hierarchy. |
| `benchmark baseline` | Complete task workspace beside a self-describing `baseline.json` whose source path matches its semantic provider/task ID. It is materialized into each selected cell while declared nonbehavioral/generated state is excluded. The copy is an isolated yadof execution input, not a resume/version snapshot. |
| `benchmark workflow request` | Immutable interpretation of live workspace `benchmark.py` after it declares evidence, opaque complete strategies, comparisons, failure/concurrency policy, interpreter, and postprocessors. Planning expands it into the workspace's single-execution `RunSpec`. |
| `benchmark evidence class` | Mandatory `structural` or `performance` declaration carried through plan, cells, reports, and inspect. Structural fake/cheap tests, adapter smoke, and benchmark smoke tests prove integration only. Performance output is descriptive and never lets the runner rank or accept strategies; budget is not an evidence-class validity floor. |
| `benchmark smoke test` | A fresh, separate benchmark workspace that runs the complete measured-workflow code path with only a smaller explicit positive evaluation budget. Its cells, arms, baselines, strategies, task code, postprocessors, policies, and dependencies remain the same as the measured benchmark; it validates execution wiring and produces no performance evidence. It is separate from the core `yadof smoke-test` midpoint-task command. |
| `benchmark replication scope` | Per-comparison interpretation of the explicit seed list. One performance seed is `exploratory`; two or more are `multi-seed`; structural evidence is `structural`. Default seed is 101 and any explicit unique integer list takes precedence. |
| `slow benchmark surrogate` | Strategy declaration `slow_surrogate=True` for repeated expensive training such as a neural network. It changes an omitted comparison generation count from 50 to 15; population remains 200 and explicit budgets are never rewritten. |
| `benchmark paired validity` | Same-baseline/same-seed eligibility for descriptive deltas and aggregates. Arms share baseline input digest, planned and attempted budgets, complete ordered generation-0 normalized population, and valid cell evidence. A mismatch preserves evidence but excludes the pair. |
| `benchmark evaluation accounting` | Planned, attempted, completed, finite, failed, and non-finite counts for one cell. Planned is population x generations and cumulative HV/AUC aligns to attempted real evaluations. Completed and finite may be smaller than attempted without automatic invalidation. |
| `benchmark simulation-error tolerance` | A collected cell with `attempted == planned`, some finite output, matching task/initial-population contracts, and an available metric may remain valid despite individual failed or non-finite simulations. Counts, diagnostic issues, and `simulation_errors_tolerated` retain the fact; missing attempts or all-infinite output remain invalid. |
| `benchmark cell` | Short ordinal directory `cells/cNNNN` containing one materialized yadof workspace, direct command logs, and one result. Full comparison/baseline/strategy/seed semantics live in `spec.json` and reports rather than paths. |
| `benchmark publication boundary` | Synchronous aggregate result/report publication after a terminal cell and before a freed FIFO slot admits another waiting cell. Any storage exception is execution-fatal; already-active cells may finish only until cancellation takes effect. |
| `benchmark concurrency plan` | Separate positive workflow `cell_concurrency` (default one) and fast/local baseline simulation-worker cap/resource-autodetection. Oversubscription is explicit and cannot change budgets, validity, persistence, or progress. |
| `benchmark terminal owner` | Foreground thread that owns Rich presentation. Pipe-drain threads persist child output and enqueue progress; fixed live rows are active cell then global benchmark. |
| `benchmark detached launch receipt` | Immediate Windows `run --detach` JSON containing PID, visible/hidden state, workspace/log paths, evidence, and exact inspect command. Detach never polls and cannot switch the caller account/session; AI agents use host execution under the interactive human account. |
| `benchmark inspect summary` | Bounded read-only first view of one workspace: status, validity, tolerated simulation errors, at most eight anomalies, active logs, current-workspace timing, next inspect command, and artifact paths. It never replans, resumes, or writes. |
| `baseline domain postprocessor` | Required uniform baseline `workspace/postprocess.py`, invoked after successful optimization with the cell workspace, shared `visualizations/domain/` directory, and short cell prefix. Missing, failed, or empty output prevents collection. |
| `user documentation` | Version-matched task-authoring and question-answering guidance under root `user_doc/`, exposed as the installed `user` audience through `yadof docs`. It serves the human user's workflow but is written primarily for an AI coding agent acting under that user's direction; the user normally directs, sets execution limits, and reviews rather than executing every documented step personally. The agent may autonomously run understood bounded work under the documented cost/risk policy. |
| `workspace` | One explicitly selected writable root owning `config.py`, fixed submit-only `submit/`, evaluate-side `job_template/`, jobs, records, checkpoints, logs, tool output, and any user-created task/debug/export directories. Extra directories do not become prepared-job inputs unless task code deliberately includes them. |
| `workspace marker` | Portable `.yadof/workspace.json` provenance published last by init. It records the template name plus package and schema identities, and never authorizes overwrite or repair. |
| `WorkspaceContext` | Immutable absolute workspace/path value used by stateful public APIs. Relative configured paths resolve from its root. |
| `effective config` | Validated immutable merge of declaratively registered core package defaults, workspace uppercase core values, and temporary core call overrides, in that precedence order. It contains campaign/framework policy, not component implementation parameters. |
| `component settings snapshot` | Private module-local frozen value constructed eagerly from explicit keyword-only arguments in snapshotted `submit/optimization.py`. It carries one search, GPSAF, acquisition, or surrogate component's resolved mathematical/training/backend values through identity and runtime; workspace authors never pass the settings object itself. |
| `task module snapshot` | Freshly compiled workspace module and local helpers from one explicitly selected `submit/` or `job_template/` source root in a temporary namespace; same-named helpers across roots or workspaces cannot contaminate each other. |
| `generation task snapshot` | One immutable temporary root containing complete copies of both coherent current `submit/` and `job_template/` trees plus configuration, selected at a generation boundary. Every strategy, backend, cost interpretation, and asynchronous surrogate task for that generation uses the copy while outputs still target the real workspace. |
| `task snapshot ID` | Provenance digest of the complete generation task snapshot. It is recorded with evidence and diagnostics but is not by itself a cache decision. |
| `interpretation fingerprint` | Digest of the snapshot inputs that normalize variables, load rawData, or calculate objectives. A change invalidates the campaign's derived historical variables/cost view. |
| `evaluation fingerprint` | Digest of the snapshot inputs that can change newly generated physical/raw evidence. A change affects later real evaluations but does not force reinterpretation when the interpretation fingerprint is unchanged. |
| `optimization fingerprint` | Provenance digest of complete snapshotted submit sources plus semantic configuration. It records source change but never decides whether recorded real evidence or persistent component state is scientifically compatible. |
| `mechanically interpretable history` | Stored raw variables/rawData that the current generation task snapshot can actually normalize, load, and convert to the current objective tuple. This is a software-processing condition, not a judgment that evidence from before and after a user edit is scientifically appropriate; that decision belongs to the user. |
| `cost-view interpretation snapshot` | The one command-local frozen list of finalized history segments together with one loaded parameter definition and `calc_cost.py` callback. A cost view decodes, schema-validates, normalizes, and recalculates each retained candidate under this one interpretation; newly published segments or task edits wait for the next view command. |
| `PARAMETERS` | Canonical unassigned `Parameter` objects in workspace `job_template/parameters_constraints.py`; each job receives a fresh assigned snapshot. |
| `expensive evaluation` | A real simulator/custom workflow producing rawData and lifecycle metadata, never authoritative cost. |
| `rawData` | Durable task evidence in schema-versioned direct `rawData/*.npz` files; subdirectories and non-`.npz` entries are invalid. |
| `rawData field selector` | The stable two-part identity `(direct NPZ basename including .npz, resolved main array key)`. The main key is the current rawData contract's `values`-before-`data` resolution. Optional `metadata.rawdata_name` and mapping traversal order are never selector identity. |
| `structured rawData sample` | One complete transient named set of schema-compatible rawData payloads. A posterior sample retains every frozen field template, axis, unit, metadata value, main shape, and dtype representation so current `calc_cost.py` can consume it; it is not a flat target vector or recorded evidence. |
| `rawData.zip` | Distributed transport archive created on the execute node and explicitly returned by HTCondor instead of `rawData/`; every member is a direct `.npz` basename with no enclosing directory. |
| `cost` | Current objective tuple dynamically calculated from rawData by the generation snapshot's `submit/calc_cost.py`. Newly authored task objectives are independent dimensionless minimization values in `[0, 1]`, using fixed task-owned physical thresholds; `0` is best and `1` is the task-level worst/error value. The framework's `inf` execution-failure sentinel is outside this normal task-cost scale. |
| `current cost` | The objective tuple calculated for an evaluation before recorder admission. It becomes usable beyond the population only after the corresponding evidence is durable; recorder failure stops the campaign instead of permitting a history gap. |
| `cost-view hypervolume` | At each recorded generation endpoint, the minimization hypervolume against fixed reference `(1, ..., 1)`. The current-generation value uses that generation alone; the all-individual value accumulates every generation seen so far. Both calculations receive only their nondominated valid points, which preserves the value while bounding cumulative input growth. Rows with any objective outside `[0, 1]` do not contribute. The plot connects the upper and lower values at the generation plotting positions with thin, translucent polylines, while retaining the shaded right-axis interval. |
| `workspace recorded data` | Workspace-local immutable segment ZIPs plus immutable optimization/surrogate event files. Normalized variables and current costs are derived. Unrelated entries below `recorded_data/` remain user-owned. |
| `campaign session` | One workspace-scoped optimization/evaluation lifetime that owns the OS campaign lock, startup segment catalog, accepted current rows, derived history view, generation snapshots, one bounded backpressured recorder writer, and publication counters. |
| `owned record envelope` | Finalizer-produced candidate evidence whose file or memory rawData has already been validated and copied/encoded under recorder ownership, so later task/job cleanup cannot invalidate it. |
| `recording segment` | Finalized immutable standard ZIP containing a bounded run/generation micro-batch of candidate metadata, NPZ members, and a manifest written last. A same-directory temporary name is atomically renamed to publish it; an old segment is never reopened. |
| `unpublished budget` | Campaign-wide exact candidate credits plus conservative peak-resident byte credits covering queued, batching, encoding, writing, and in-flight envelopes. Admission waits when credits are exhausted and releases them only after publication. |
| `recording failure` | An oversized envelope, exhausted write attempts, or unexpected writer death that prevents durable publication. It raises `RecordingError`, stops the campaign before later evaluation, and is distinct from an individual simulator/rawData/current-cost failure. |
| `package worker support` | The single reserved `worker_misc.py` copied as a direct job-local file; it owns dependency-free invariant execute lifecycle, paths, metadata, machine identity, rawData preparation, cleanup/error handling, and flat zip creation without sending yadof to workers. |
| `task-variable code` | Behavior that can change with the task: evaluate-side simulator/evidence code belongs in `job_template/`; cost and complete optimization composition belong in `submit/`; cross-task invariant behavior belongs in yadof. |
| `self-contained parameter snapshot` | Assigned job-local `parameters_constraints.py` with a minimal local `Parameter` representation and no yadof import. |
| `direct workflow submission` | Windows HTCondor contract in which `workflow.py` itself is `executable` with `transfer_executable=True`; there is no yadof launcher. |
| `job_static_hash` | Definition-oriented hash of task/worker inputs that excludes runtime metadata and per-candidate assignments. |
| `standalone smoke test` | `yadof smoke-test`: exactly one midpoint real task, no generation/per-job/whole-generation timeout; edited tasks require explicit real-task intent. |
| `run smoke` | Optional pre-run real-task smoke chosen by workspace config unless `--smoke-test` or `--no-smoke-test` overrides it. Failure prevents generation submission. |
| `local mode` | Prepared workflow subprocess execution using the installed package and selected workspace. |
| `fast mode` | A single-host evaluation backend using bounded reusable spawn workers and task-owned `evaluation.py`. It returns named memory rawData directly to the parent recorder, creates no durable per-candidate job folder, and replaces a worker after task failure, crash, or timeout. |
| `fast task kernel` | Callable `job_template/evaluation.py:evaluate_rawdata(parameters, context)` for a fast-compatible task. It receives read-only assigned named values and a no-job-path context, may run external local software, and returns schema-valid named rawData payloads plus optional JSON diagnostics, never cost. |
| `fast candidate scratch` | Ephemeral candidate-specific directory below `FAST_EVALUATION_SCRATCH_DIR`, disjoint from task/jobs/history. It exists only for external software that needs files, has no job/evidence/recovery meaning, and is reclaimed by the parent on every outcome. |
| `memory-backed rawData` | A unique direct `.npz` basename paired with an in-memory schema-valid payload. Recorded data encodes it without pickle into the same job/evaluation-namespaced archive layout used by file-backed evidence. |
| `distributed mode` | HTCondor transport preserving the local job/result/recording contract. |
| `HTCondor runner` | `yadof.evaluate_manager.condor_runner`, which writes submit files, submits/polls/collects, records ClassAds, and diagnoses but never repairs the pool. |
| `slot user` | Low-privilege Windows HTCondor execution account; normal policy is `run_as_owner=False`, `load_profile=True`. |
| `execute machine` | Computer name primarily sampled by package worker support inside the running workflow process and returned as `execute_machine` in `individual_metadata.json`. For a timed-out HTCondor job that cannot return that file, `condor_execute_machine` is a lower-priority submit-side fallback parsed from the job's own Condor user log; older records can derive the same fallback in memory from their stored `condor_log_tail`. Neither path overrides the worker value, and a job with no relevant execute segment remains `unknown`. |
| `Condor execute site` | The machine and optional slot name attached to one event-001 execution segment in a job-local `condor.log`. It is scheduler-observed provenance, recorded with source `condor_user_log` only as a timeout fallback rather than as worker-reported identity. |
| `adaptive resource request` | Workspace-history-derived memory/disk request; CPU remains a user policy. |
| `shared resource calibration` | Backend-neutral history selection, unit normalization, high-tail trimming, and bootstrap estimation over common CPU/memory/disk evidence. Local and distributed execution consume this contract instead of maintaining separate estimators. |
| `adaptive local concurrency` | Effective local worker count bounded by population size, the configured cap, physical CPU capacity, available memory, free jobs-disk capacity, and a host reserve. It may be smaller than the cap; smoke execution remains one worker. |
| `yadof resource retry` | Fresh bounded submission after standard memory/disk holds, doubling only the exhausted request and preserving attempt diagnostics. |
| `adaptive time limit` | Per-normal-job execution budget derived from smoke/prior generation or fixed config, enforced both by Condor `allowed_execute_duration` and the yadof submit-side execution watchdog; it is separate from the whole-generation deadline. |
| `submit-side execution watchdog` | yadof's distributed per-job clock derived from the current `condor.log` execute segment; at the adaptive limit it finalizes timeout locally and attempts bounded `condor_rm` cleanup without waiting for removal confirmation. |
| `optimization strategy` | The one immutable complete generation method returned by snapshotted `submit/optimization.py:build_optimization()`. Its explicit factories are the sole workspace source for component parameters. Package components provide narrow GPSAF, pymoo search, conditional-INR, and real-evaluation mechanisms but no competing complete-method registry or config selector. |
| `strategy semantic signature` | Deterministic SHA-256 identity over the selected strategy/component/backend identities, backend versions, yadof-controlled parameters, and parameter/objective names. It is separate from source hashes and selects the retained strategy namespace. |
| `GPSAF` | A composable yadof-owned alpha/beta/gamma/exploration assistance component with real-evaluation validation; the workspace injects its pymoo search and rawData-surrogate components and sets GPSAF values only through explicit `gpsaf()` kwargs. |
| `surrogate cost interval` | Per-objective min/max across conditional-INR ensemble members after predicted rawData is converted by current cost policy. |
| `joint rawData posterior` | A backend-neutral derived distribution over complete rawData-valued functions of normalized parameters. One persistent sampler fixes draw identities before candidate chunking, and the same draw spans every candidate, field, and derived objective. It is transient and never becomes recorded evidence. |
| `rawData function draw` | One stable possible function selected by a persistent posterior sampler. Repeated candidates have identical values within it, while candidate permutation, chunk size, and chunk call order only reorder or partition its evaluations; they never resample its member, weights, mask, or latent state. |
| `posterior support diagnostics` | Honest metadata describing posterior kind, requested/actual draws, seed, stable draw/source identities, signatures, limitations, and support. A finite posterior reports nominal `unique_support` as the count of distinct available source functions even when draws repeat, plus effective distinct drawn sources that remain complete after inference/current-cost projection; continuous or unknown support reports `unique_support=None`. |
| `posterior calibration artifact` | A self-verifying adjunct bound to one exact posterior state/strategy/schema, checkpoint hashes, training provenance, held-out design partition, policy, and label/head/loss identity. It may carry conservative per-field spread scales and one member-paired applicability mapping only after frozen gates pass; failed artifacts remain explicit identity-scale `uncalibrated`, expose no probability coefficients, and are non-transferable. |
| `calibrated rawData posterior sampler` | A persistent finite sampler wrapped by a successful posterior calibration artifact. It enumerates each unique member once and scales complete field draws around the unchanged empirical mean without reordering the shared member axis, changing candidate/chunk coherence, or introducing observation noise. |
| `posterior exploitation readiness` | A transient typed capability aligned to one candidate pool. It permits preference only when architecture performance is accepted, posterior calibration is exact-state-bound and transferable, observation noise is absent, state/artifact signatures match, and applicability is calibrated or explicitly not applicable. It carries no variance/training-loss shortcut; current shipped posterior components return blocked readiness. |
| `calibrated applicability gate` | A strategy-identity-bound threshold, boundary width, calibration-policy SHA-256, policy version, and boundary/low exploration ordering that may consume only typed calibrated `P(smooth)`. Below-threshold rows cannot exploit; auditable low/boundary rows may still receive common real evaluation through the explicit exploration quota. |
| `RawDataCostProjector` | The thin submit-side adapter that validates complete predicted named rawData against a frozen schema template, denormalizes candidates with a frozen `CostInterpreter`, invokes current task cost, and returns joint objective samples plus validity and bounded diagnostics. Finite task fallback `1.0` remains valid; schema/callback/width/non-finite failures are invalid. It never records predictions. |
| `conditional-INR posterior adapter` | The explicit `conditional_inr_posterior()` component wrapper over the unchanged conditional-INR ensemble. A persistent seeded sampler fixes one loaded member for every draw, reuses that member across candidates/fields/objectives, reconstructs full stored-grid named rawData, and reports finite uncalibrated support. It has a separate semantic identity and does not alter `conditional_inr()`, GPSAF, viewer, training, or checkpoint mathematics. |
| `hierarchical CAE surrogate` | The opt-in experimental `hierarchical_cae()` full-grid rawData component with selector-specific scalar/Conv1d/Conv2d codecs, global/optional-group/field-private teacher latents, shared-codec parameter-predictor members, atomic checkpoints, and coherent finite member draws. Its component-local `data_filter_mode` defaults to `none`; the existing `frequency` mode can use task diagnostics or declared frequency/morphology thresholds, including spectral high-frequency energy, to form training weights/masks without deleting or rewriting rawData. Gate 0 v5 and exact-signature v8 remain frozen failed historical experiments. A later 24-cell base benchmark found strong synthetic-antenna, mixed SAW, and weak Chrono end-to-end evidence; its sealed all-cell gate was false, but that boolean is no longer a global performance verdict. Current exact states still have no usable calibrated posterior, so qNEHVI exploitation remains blocked on capability-specific readiness while deterministic CAE research is assessed by case, metric, and intended use. |
| `PCA/SVD rawData surrogate` | The opt-in deterministic `pca_svd()` GPSAF component. It fits a centered PCA or uncentered truncated-SVD basis independently for each exact named rawData field, then maps normalized parameters to concatenated coefficients with ridge regression and derives costs through current task code. It publishes zero-width intervals and has no posterior/readiness capability. |
| `low-rank reconstruction oracle` | A diagnostic-only projection of already-known rawData through a basis fitted from training rows. It may encode validation truth to measure representation ceiling, so it is never candidate prediction, optimizer evidence, or a deployable surrogate score. |
| `rawData frequency filter` | A versioned JSON-safe task declaration for hierarchical CAE's `frequency` mode. It maps explicit assessment, ordered diagnostic rules, or a missing-diagnostic spectral/morphology fallback to design/field regimes, loss weights, shared-token weights, residual targets, and applicability labels. It is semantic/checkpoint identity, contains no executable callback, and never changes source rawData or current cost. |
| `applicability score` | A surrogate member's uncalibrated estimate of `P(smooth)` or equivalent regime suitability. It describes epistemic/structural state, retains the same member identity across candidates and fields in a posterior draw, and is not independent Gaussian observation noise or an implicit rule based on loss, cost, or member min/max. |
| `design-by-field robust aggregation` | Hierarchical-CAE loss policy that first averages pointwise error within every design/field, then optionally caps and weights that matrix before a field macro reduction. No-policy behavior uses unit weights; a low-trust curve does not discard valid scalar fields from the same design. |
| `discrete qLogNEHVI backend` | The Gate 2-origin scorer that combines fixed real baseline costs with aligned joint candidate objective draws, rejects incomplete MC draws as a whole, converts yadof minimization to BoTorch maximization once, and delegates qLogNEHVI numerics to BoTorch for caller-supplied discrete q batches. It has no candidate generation, generation orchestration, real evaluator, recorder, or pending/outcome contracts. |
| `discrete qNEHVI acquisition` | The public `qnehvi()` family component that validates multi-objective/reference/support controls and selects a batch through deterministic greedy multi-start calls to the discrete qLogNEHVI backend. It owns no candidate pool, posterior projection, real evaluation, or durable evidence. |
| `posterior-assisted strategy` | The opt-in `posterior_assisted()` complete strategy that reuses private pymoo candidate mechanics, typed readiness, a fixed real Pareto baseline, one persistent schema-bearing sampler, chunked current-cost projection, qNEHVI exploitation, explicit real exploration, and common real evaluation. Any current scientific blocker or soft selection failure produces a full real-search population; support rejection and recorder failure remain hard stops. |
| `surrogate evidence and release program` | Versioned evidence that separates CAE representation/prediction/coordinate/resource tradeoffs from exact posterior capability, acquisition mechanics, optimization quality, engineering cost, and the user-owned default decision. CAE performance is reported continuously by case and intended use rather than collapsed into an all-cell gate. Schema/state/calibration/acquisition integrity may still make one exact posterior capability unavailable, and structural benchmark evidence never proves optimization benefit. Valid same-budget arm pairs remain usable even when another arm is unresolved. |
| `real-field-balanced surrogate training` | Conditional-INR policy that trains only on recorded real rows or seeded bootstrap draws, standardizes each rawData query by its recorded mean and standard deviation, uses seeded without-replacement query sampling balanced across active rawData fields, averages pointwise Smooth L1 inside each field, and macro-averages fields equally. Its linear standard-score decoder may extrapolate beyond recorded rawData extrema. Task code cannot supply weights or synthetic targets. |
| `surrogate semantic state signature` | SHA-256 identity over active strategy signature, checkpoint method/training policy, parameter names and normalization-defining ranges/levels, rawData schema/query tables, INR training configuration, and relevant runtime version. Recovery is restricted to `runs/<strategy>/components/conditional-inr/`; incompatible or inactive artifacts remain retained. |
| `staggered surrogate training` | Submit real jobs first, then train at most one workspace-local background model while execution is busy, subject to lag bounds. |
| `packaged adapter` | Read-only reusable resource listed/copied by `yadof task`; active jobs use only the workspace copy. |
| `external simulator Python runtime` | A separately provisioned absolute interpreter and environment used only through an OS subprocess boundary. It is not a yadof host environment: yadof does not activate it, import its packages, install itself there, or select it through PATH. A Windows child may receive selected-prefix native-DLL directories in its own PATH copy without changing parent/user/machine state. |
| `PyChrono subprocess protocol` | The versioned JSON/NPZ boundary implemented by the packaged `chrono_com.py` resource between a yadof task-side parent and task-owned PyChrono child. It owns explicit interpreter resolution, isolated candidate execution, validated evidence, bounded diagnostics, and backend-equivalent rawData publication without either runtime importing the other framework. |
| `software task namespace` | The software-identifying CLI level below `yadof task` for non-generic actions, such as `yadof task hfss`; it prevents different adapters from competing for an ambiguous generic action name. |
| `surrogate viewer` | The optional, explicitly launched `yadof view surrogate` inspection tool below `yadof.tools.surrogate_viewer`; its default mode is a desktop GUI, while `summary` and `audit` provide terminal text/JSON. Every mode reads one workspace's current task, real evidence, and checkpoints without training, executing workflows, or writing workspace state. |
| `surrogate text report` | A schema-versioned or human-readable stdout result from `yadof view surrogate summary|audit`. Summary reports metadata without model inference; audit reports selected cross-generation mean-error matrices after inference. Optional progress is isolated on stderr. |
| `task-specific test` | Test tied to a concrete model/design/objective. It belongs in a disposable/external workspace, not the generic default suite. |
| `user` | Directs preparation of workspace tasks, defines execution limits, explicitly authorizes long or consequential campaigns, and inspects results without maintaining system infrastructure. The normal interface is a user-directed AI coding agent reading `user_doc/`, which may run understood bounded low-cost work under the documented policy. |
| `administrator` | Installs dependencies and maintains HTCondor/software/hardware; canonical guidance lives under `admin_tool/admin_doc/` and executable resources remain in sibling directories under `admin_tool/`. |
| `manual toDo` | Root `dev_doc/toDo/*.md`; reading supplies context but execution requires an explicit user request. |
| `automatic toDo` | Low-priority `toDo/auto/` handoff that receives a mandatory bounded match check against already in-scope evidence before normal work is reported complete. It executes only when that check finds the document's objective condition and does not authorize an unrelated repository scan. |
| `persistent automatic toDo` | An automatic toDo whose `Obsolete Rule` is `persistent`; it still triggers automatically on a bounded match, is not retired by age, and remains active after each occurrence when its completion rule defines recurring work. |
| `change record` | Append-only time-named explanation under `dev_doc/change_records/`; not read by default. |
| `benchmark provenance digest` | Recorded driver, baseline, strategy, or study hash used for traceability and display only. It is never compared with current files to reject recovery. |
| `surrogate shared primitive` | Component-neutral atomic artifact publication, bounded training-event recording, or deterministic finite-member selection proven equivalent in conditional-INR and hierarchical CAE. It owns no model, schema, namespace, quality, scheduler, or selector policy. |
