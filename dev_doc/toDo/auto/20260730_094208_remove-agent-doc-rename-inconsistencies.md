# 清理 `agent_doc` 改名遗留不一致

## 背景

- 用户工作流文档已经从 `agent_doc/` 重命名为 `user_doc/`，安装文档受众也从
  `agent` 改为 `user`。
- 这次改名跨越源码目录、wheel/sdist 资源、CLI、README prompt、开发契约、架构、
  蓝图、术语和测试。以后在正常工作中仍可能遇到遗漏的旧路径、旧受众名或错误表述。
- `user_doc` 表示文档服务于人类用户的工作流和权限边界；这些文档仍主要由受该用户
  指挥的 AI coding agent 阅读和执行。普通语义中的 “AI agent” 不是旧命名遗留。

## 目标

- 在正常任务已经进入的范围内，发现并修正所有由本次改名造成的当前设计不一致。
- 最终让当前代码、当前文档、测试命名、提示词、CLI/API、资源路径和发布产物表现得
  好像工程从未把用户工作流文档命名为 `agent_doc`、也从未公开 `agent` 文档受众。
- 保持清晰说明：人类用户负责指挥、审查和授权，AI agent 是 `user_doc` 的主要
  阅读者和执行者。

## 指导

- 按 `dev_doc/skill/toDo.md` 的范围受限自动触发检查执行：只检查正常任务已经接触的
  文件、直接相关调用/测试/文档和当前 diff，不为了本 toDo 单独扫描整个仓库。
- 匹配项包括但不限于：
  - 当前源码、配置或文档中的 `agent_doc/` 路径；
  - `yadof docs ... agent`、`DocumentationKind = "agent"` 或同义旧 API；
  - wheel/sdist 中的 `agent_doc` 资源目录；
  - 把这一组文档称为 “agent documentation” 的当前标题、链接、变量名或测试名；
  - 仍指向旧入口的 prompt、示例、架构、蓝图、术语和包成员断言。
- 直接改成当前 `user_doc` / `user` 契约，不添加旧名兼容别名、迁移回退或双目录。
- 测试若能通过断言允许的当前集合获得同等或更强覆盖，应避免仅为了负向断言而永久
  保存旧名称。
- 不要误删对 AI agent 的正常描述。文档必须继续明确其主要执行者是受人类用户指挥
  的 AI agent。
- `dev_doc/change_records/` 和 `dev_doc/obsolete/` 中准确描述历史的旧名称不算当前
  不一致，不要违反历史文档契约去改写；当前文件若把历史名称当作有效入口则仍需修正。
- 每次匹配的修正和汇报继续遵守对应自动 toDo 的范围、证据和验证要求。

## Completion Rule

- 对一次自然触发而言：已进入范围的旧命名不一致已修正，相关当前入口和测试已验证，
  且没有新增兼容别名。
- 在本文件仍有效期间继续保留，以捕获后续正常工作中遇到的遗漏；若一次经明确授权的
  完整审计证明所有当前表面均只使用 `user_doc` / `user`，可按通用完成规则提前归档。

## Obsolete Rule

- 文件名时间戳后七天过期，即本地时间 `2026-08-06 09:42:08` 时仍有效，严格晚于该
  时刻后按自动过期规则移入 `dev_doc/obsolete/`。
